# Design audit — findings catalogue, September 2026

LAN-224. One auditor walked every page file under `src/app/` at desktop
(1440×900) and measured 375×812, on the deterministic local seed, on
3–4 September 2026 at `main` commit `4a3efa9`. Every finding below names the
screenshot in [`screens/`](screens/) that shows it. Nothing here is fixed; the
brief that follows from these findings is [`brief.md`](brief.md).

**How to read a finding.** Id, route(s), screenshot(s), one sentence saying
what is wrong, the `docs/ux/standards.md` rule it breaks if any, a one-line
recommendation, a size (S / M / L), and a class: `visual` (theme, token, or
component change; no behaviour change) or `product` (changes what a screen does
or says; Brian's decision, returned here as a finding and never proposed as
done). `product` rows are also listed in the register at the end in the
decision-coverage shape.

**Two things the screenshots show that are not findings.** The round "N" badge
at the bottom left of every capture, and the "Compiling…" and "1 issue" pills
on a few, are the Next.js development overlay, not the application. And the
roster and recruitment boards' behaviour (columns, pinned editing, filters,
banding, horizontal scroll) is out of scope by Brian's decision of
3 September 2026; findings on those two routes are limited to tokens and shared
chrome.

States that could not be captured, and why:

- `/rsvp/[token]` valid states (invitation, declining, saved, already
  responded, event cancelled). The RSVP link is carried only by the email rung
  of the ladder; the WhatsApp template carries the answer tokens
  (`/a/[token]`), which were captured. The email rung for the seeded invitation
  is scheduled days ahead and the local scheduler does not run future jobs. The
  security-uniform not-found page was captured, and its copy is owner-fixed.
- `/operate` and `/dashboard` for an **unlinked** account. `npm run
db:seed-user` always targets the protected review address, sign-up is
  disabled, and creating another local auth user needs an unfenced script. The
  screen is `OperatorAccountState` with the unlinked copy from `slice-ux.md`
  §8; the inactive variant of the same component was captured.
- `/operate/admin/operators/new` search results and an invitation-pending
  operator. The search step's result selector was not found within 60s in the
  capture script; the empty form was captured at both widths.
- `/reset-password` valid form. Captured at desktop via the Mailpit recovery
  link; the phone capture of the same state came from the first run.

## Method

Captures were driven by a Playwright script in the agent's scratchpad using the
same login helper and viewports as `scripts/visual-preflight.mjs`, because the
preflight signs in only as the operator and cannot reach anonymous, token, or
coach pages (the pattern LAN-206 recorded). One preflight run at the final head
is the repository's own evidence. Mutating steps (issuing a club link, minting
the sign-up code, reissuing one invitation, withdrawing one consent, cancelling
one spare event, deactivating and restoring the coach's operator account) ran
last, on rows not used by any pristine capture, and the database was reset and
reseeded afterwards. No application code, theme, or configuration under version
control was changed. The only non-seed strings on screen are the two fixed
local review logins (the owner's own address and its `+coach` alias), which the
repository already names in `scripts/lib/local-review-account.mjs`; no password
is visible.
